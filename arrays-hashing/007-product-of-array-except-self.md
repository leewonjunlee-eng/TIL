# Product of Array Except Self

## 접근법

각 위치에서 자기 자신을 제외한 모든 원소의 곱을 구해야 한다.

처음에는 전체 곱을 구한 뒤 현재 값을 나누는 방법을 생각할 수 있다. 하지만 문제에서 나눗셈 사용을 금지했고, 0이 포함되면 별도 예외 처리가 필요하다. 그래서 왼쪽 누적 곱과 오른쪽 누적 곱을 나누어 계산했다.

answer는 반환 배열이면서 왼쪽 누적 곱을 저장하는 공간으로 사용한다.

### 1. 왼쪽 누적 곱 저장

먼저 모든 값을 1로 채운 answer를 만든다. postfix 변수는 현재 위치의 왼쪽에 있는 값들의 곱을 저장한다.

    answer = [1] * len(nums)
    postfix = 1

현재 숫자를 answer에 곱하지 않고, 다음 위치에 누적 곱을 저장한다.

    for index in range(len(answer) - 1):
        postfix *= nums[index]
        answer[index + 1] *= postfix

예를 들어 nums가 [1, 2, 3, 4]라면 첫 번째 순회가 끝난 뒤 answer에는 다음과 같이 저장된다.

    [1, 1, 2, 6]

각 위치에 자기 자신보다 왼쪽에 있는 값들의 곱이 들어 있다.

### 2. 오른쪽 누적 곱 결합

postfix를 다시 1로 초기화하고, 이번에는 오른쪽에서 왼쪽으로 이동한다. 현재 위치의 오른쪽 값들을 곱한 뒤, 이미 저장된 왼쪽 누적 곱과 곱한다.

    postfix = 1

    for index in range(len(answer) - 1, 0, -1):
        postfix *= nums[index]
        answer[index - 1] *= postfix

두 번의 순회가 끝나면 각 위치에는 왼쪽 곱 × 오른쪽 곱이 저장된다. 따라서 현재 원소는 자연스럽게 제외된다.

## 시간·공간 복잡도

- 시간: O(n)
- 공간: O(1) — answer는 반환해야 하는 배열이므로 추가 공간에서 제외한다.

왼쪽과 오른쪽을 각각 한 번씩 순회하므로 전체 연산 횟수는 2n에 비례하고, Big-O 표기에서는 O(n)이다.

## 막힌 지점

- 전체 곱을 나누는 방법은 문제 조건인 나눗셈 금지에 어긋난다.
- 0이 있는 경우 나눗셈 방식은 추가 예외 처리가 필요하지만, 누적 곱 방식은 0도 그대로 처리한다.
- answer = [1] * len(nums)는 길이가 nums와 같고 모든 값이 1인 리스트를 만든다. 곱셈 누적의 시작값으로 1이 필요하다.
- 오른쪽에서 왼쪽으로 순회할 때 range(len(answer) - 1, 0, -1)은 마지막 인덱스부터 1까지 이동한다. 0까지 포함하려면 끝값을 -1로 설정해야 하지만, 이 문제에서는 다음 위치인 index - 1에 값을 곱하므로 1까지만 확인한다.

## 더 빠른 방법

현재 풀이가 이미 시간 O(n), 추가 공간 O(1)이라 점근적으로 더 빠른 방법은 없다. prefix 배열과 postfix 배열을 각각 만들 수도 있지만, answer와 변수 하나를 재사용하면 추가 메모리를 줄일 수 있다.

코드를 한 번에 처리하려고 해도 왼쪽 정보와 오른쪽 정보가 모두 필요하므로 최소 두 방향의 누적 계산이 필요하다. 따라서 이 문제에서는 두 번 순회하는 현재 방식이 시간과 공간의 균형이 가장 좋다.

## 다음에 기억할 한 줄

나눗셈 없이 자기 자신을 제외한 곱을 구할 때는 answer에 prefix를 저장하고, 뒤에서 postfix를 곱해 완성한다.
